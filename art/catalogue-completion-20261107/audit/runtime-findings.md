# Runtime rotation and click-through audit

2026-11-07. Read-only investigation of `E:/Repos/CapitalEmpire/worktrees/theme-consistency`. No runtime files changed, no build, test, server or rebuild POST started. Owner servers remain untouched. Static source evidence only; art quality and source completeness belong to the companion inventory.

## Result

**The game does not currently offer eight selectable rotations for every building and prop.** Complete source sheets alone cannot fulfill the request. The placement tool, event structure saves, picture mapping, footprints and seated crowds need coordinated support.

`runtime-registry.json` records 191 subjects in the union of existing corner and axis mappings. There are 171 original corner mappings, 60 axis sets and 9 supplemental corner sets. Forty-nine subjects have all eight mapped IDs present after the Studio removal list is filtered. These include plants the owner excludes, and the count does not prove eight different accepted image pixels or correct light/geometry. It must not be reported as an all-catalogue completion count.

## Placement and rotation

- `src/game/lots/preset-art.ts:24` `fourViews()` validates four corner IDs; `:49` `axisViews()` validates a separate set of four screen-axis IDs. `:66` `axisSetOf()` finds the axis set from a subject's views.
- `src/game/lots/preset-art.ts:72` `roadView()` and `:91` `drawnView()` implement eight ROAD headings: corner sets on axis roads and N/E/S/W sets on odd roads. `src/game/lots/presets.ts:9` has four prop-relative quarter turns, while `:11` has eight road orientations. There is no uniform eight-position prop-facing type.
- `src/game/lots/preset-art.ts:110` `turned()` reduces its argument modulo four and chooses a four-view set. Eight-facing vehicles move by two facing slots for each quarter turn. Items lacking matching art retain the original ID. A fence exchanges x/y run art; selected legacy axis props can still return `flip:true`.
- `src/game/golf/propstool.ts:98` `pictureOf()` uses `turned()`; `:105` `turnMode()` identifies four-view pictures, variants, or none; `:113` `views()` hardcodes four for genuine rotations. `:215` `turn()` cycles only those four when holding or selecting a prop. It never crosses between corner and axis sets. Variant cycling is a different shape/picture, not evidence of another angle.
- `src/ui/course/PropsPanel.tsx:46` exposes that turn action with R/button. Missing-art items are explicitly one picture. New props with IDs `newprop:*` are plain one-view decor unless a rotation registry is added; a collection of similarly named new props is not automatically one eight-facing item.
- `src/game/mirror.ts:24` `drawnAs()` substitutes paired genuine corner/axis views for many old flip requests, preserves upper-right light and suppresses mirroring for buildings/nature/kit art. This protects lighting; it does not create missing views. Other ordinary prop kinds can retain flips. `src/game/newart.ts:185` `lookOf()` may replace missing old building art with another building of its family, so a visible picture is not proof that the requested subject was generated.

The existing system's eight ROAD headings mean eighth turns (45 degrees). The owner's phrase “four normal plus four 8 degree turned” must stay bound to the actual approved Video Vault/Arcade references and source geometry; do not silently claim the engine supports arbitrary physical 8-degree yaw increments. Save the explicit eight slot names and approved geometry in the import manifest.

## Golf event structures and grandstands

- `src/game/golf/structure-art.ts:7` `STRUCTURE_SPRITE` maps many different functions to stand-ins. All `standS`, `standM`, `standL`, `rangeStand` use `golf:grandstand-s`; `foodTruck` uses the food tent, many hospitality/helipad types use a pavilion, and media/hotel use a clubhouse. Not independent artwork.
- `src/game/golf/tents.ts:23` defines different stand capacities and footprints: S=200 seats (8x4 tiles), M=1,000 (20x6), L=4,000 (40x10), practice=600 (12x4). The gameplay capacities already differ; the artwork and row geometry do not. There is no worn/renovated visual-level field in the structure catalogue.
- `src/game/golf/eventtool.ts:36` `PlacedEventStructure` stores only optional `rotated:boolean`; `:80` `structureRect()` swaps rectangular width/height. `src/game/engine.ts:4205` passes that boolean as a prop flip, not an eight-facing ID.
- `src/game/engine.ts:4168` `eventStructurePending` has only typeId/mode. Actual map placement at `:5378` and ghost candidate at `:10984` omit orientation entirely. Even the optional bool is not selectable in that normal click path. `:4304` re-creates structure props from that representation.
- Runtime axis sets contain only one golf subject, `golf:clubhouse-shanty`. Original corner sets exist for ten golf/building subjects: cart garage, clubhouse, driving range, halfway pavilion, pro shop, clubhouse shanty, food tent, grandstand S, leaderboard, toilet block. Most course equipment has no eight-view registration.
- `src/game/golf/galleries.ts:32` hardcodes every grandstand's seated focus toward screen bottom; `src/game/crowdview.ts:76` renders up to 90 seated people with twelve per row, and `:90` shifts every higher row toward screen top independently of facing. Adding rotated empty-stand art without seat anchors would leave people floating or facing away.

Recommended stand deliverables: small/medium/large/practice variants in worn practical mid-century construction and upgraded attractive construction, eight separately authored views for each, empty seats, seat-row/aisle coordinates by view, stair-entry positions, footprint, physical dimensions and gameplay capacity stated separately. Worn buildings should be plausible inexpensive 1950s structures maintained into the 1985 setting, not fantasy goblin shacks. Retain existing IDs and old save indices; new style IDs or visual-level mappings should append.

## Click-through scene images

- `src/ui/SceneCard.tsx:10` lazily requests `src/assets/scenes/*.webp`; it already supports large pictures and multiple view tabs. `src/game/scenes.ts:29` `SceneRef` covers range, club, lot business, farm and iconic place. It has no general town-house or event-facility case.
- `src/game/engine.ts:3919` `openScene()`, `:3933` `sceneOf()`, `:3966` `inspectScene()` bind actual clicked props to those supported scene kinds. `:3963` `sceneSubject()` resolves the drawn art's subject. Range pieces open their associated detail view; businesses use `lotPlaceOf()` and raw/drawn subjects; farms use the farmhouse scene. An ordinary town home does not have a generic scene selection path.
- `src/game/scenes.ts:187` `LOT_PLACES` has 13 business types ready for art: video, diner, gas, barber, hardware, grocery, pharmacy, tackle, arcade, laundromat, bakery, post, fire. Additional unsupported business subjects need a mapping. The existing places remain hidden until art for their state exists.
- Live `src/assets/scenes/manifest.json` has **17 imported pictures**: range road, hitting bays, pro-shop inside, practice green, home caravan, home farmhouse, video-store inside and video-store outside all have rundown/upgraded pairs; home cottage has rundown only. Therefore most businesses, ordinary houses, clubhouse tiers and iconic places currently have no imported large scene.
- `src/game/scenes.ts:39` `pickPicture()` deliberately never shows a rich/upgraded state for hard times. Good times can fall back to the rundown image of the same scene. Preserve that behavior and add genuine paired variations, not one rich scene for all upgrade levels.
- `scripts/assets/prep-scenes.mjs` imports `<slug>/<slug>-<state>-vN.png` to WebP, records source hash/version, and can do `--dry`. Generated images in another worktree or folder are not automatically available. This importer chooses the highest version and skips explicit rejects, but it is not a complete approval gate: do not run it over unreviewed batches. Import selected reviewed outputs only in the implementation ticket.

## Characters, identity and portraits

- Current runtime library has **15 town looks**, **15 spectator looks**, **10 golfer looks**. `src/game/library.ts:1047` has eight genuine directions and nine town frames per direction (idle+eight walk). Spectators have 25 total frames per direction (idle/walk/clap/cheer/sit/sit_clap); golfers have 29 (idle/walk/drive/putt). `src/game/ext/pedestrians/pedestrians.ts:70` `FACING_ROW` maps each heading to itself with `mirror:false`.
- These sheets are rendered animation, not static eight-view object sheets. Large portraits must match the existing character's source look and must not replace walk/idle/swing/crowd frames. Avoid repainting isolated animation frames independently; consistency comes from the person model, rig, clips and fixed render camera. Existing people pipeline is documented in `docs/HANDOVER-PEOPLE.md` and `docs/SPECTATOR-ART.md`.
- `src/game/engine.ts:7990` `youThingAt()` permits clicking town walkers, club pros, range golfers and everyday course golfers in Walk mode, then walking up to talk. Tournament spectators are not included in this person-hit loop. `:8115` `youTalkTo()` creates a text-only card. `src/ui/golf/YouCards.tsx:83` `TalkCard` explicitly says portraits await T243. No portrait atlas/manifest or portrait renderer exists in that card.
- Town walker names are derived from look index **and current rounded x/y**, so moving one can change who they appear to be. `WalkerView` contains position/facing/frame/person-look but no stable instance identity (`pedestrians.ts:74`). Range names combine look and current array slot. Golfers/staff have stronger roster identities. Binding a portrait merely by transient position/name would be incorrect.

Recommended portrait contract: stable person instance ID plus look/archetype ID, role/job, name, generated short bio, matched portrait manifest key; portrait lookup by look/archetype with optional hard-times/good-times variant. Keep images on demand when cards open. Extend hit testing to course spectators and staff as necessary. For ordinary background walkers create deterministic identity from persistent spawn/home identity instead of current coordinates. Portrait art is cinematic eye-level/slightly raised, opaque, in the same illustrated materials/color/light style; do not reuse a 2x2 isometric building guide for portraits.
