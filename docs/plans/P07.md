# P07: Save versioning and migrations (Alpha 1.0)

Status: **draft for the owner's approval** (second lead, 2026-10-24). Issue #70.

## Where we are (verified in the code)
- **Storage:** one gzip-compressed JSON save in IndexedDB (`capital-empire` / `saves` / slot `town`, src/game/save.ts). The localStorage limit doesn't apply; IndexedDB allows hundreds of MB. A v2 save in localStorage is still migrated on read.
- **Versions:** `SAVE_VERSION = 5`. `upgradeSave` reads v5, v4 and v3. Anything else returns `null`: a save from another map size, an unknown version, or one that fails to unzip or parse.
- **The golf state** (`SaveV5.golf`, a `GolfSave` with `v: 1`) has grown by **optional fields with normalizers**: `normalizeGolfSave` (parcels, structures, cards, poorYears), `loadCourseHeight` (T027 `height`), `normalizeProgress` (T033 `progress`; missing = an experienced player). tests/golf-save-compat.test.ts pins old golf shapes, but only with hand-written objects.
- **The real risk:** when `readSave` gives `null`, the engine starts a new game (engine.ts `if (!save && this.newGolfGame())`). The autosave 800 ms later **overwrites the slot**. A tester who opens an older build after a newer one, or whose save is corrupt, loses that save silently.

## Decisions (proposed)
1. **Two kinds of change.**
   - *Additive* (a new optional field, read through a normalizer with a safe default): no version bump. This is the rule we already follow; it becomes written policy here and in CLAUDE.md's project facts.
   - *Breaking* (a field changes meaning or shape, or is removed): bump `SAVE_VERSION` and add one migration step.
2. **A migration chain.** `upgradeSave` becomes an ordered table `MIGRATIONS: { from: number; up(d): d }[]` applied step by step up to `SAVE_VERSION` (3→4→5→…). Each step is a pure function with its own test. The v2 localStorage path stays as it is.
3. **Never overwrite what we can't read.** `readSave` returns `{ save, status: 'ok' | 'none' | 'future' | 'corrupt' | 'otherMap', version? }`.
   - For `future`, `corrupt` and `otherMap`, the raw bytes are first copied to a backup slot `town-backup-<status>-<version|time>` (kept until the player deletes it).
   - Only then does the game start fresh, with a toast: "This save is from a newer build (v6). It is kept as a backup; a new game started."
   - The gear menu lists the backups, with Download and Delete.
4. **A backup before every migration.** When a save loads through one or more migration steps, the original bytes go to `town-pre-v<old>` once, before the first autosave of the migrated game. One old copy is kept per version.
5. **A build stamp.** Every save records `build: { app: <package.json version>, sha: <git short sha at build time> }` through Vite `define`, so a bug report says which build wrote it. Informational only, never used to refuse a save.
6. **Export / import.** The gear menu gets "Download save" (the gzip file, `capital-empire-<date>.cesave`) and "Load save file" (it goes through the same `upgradeSave` path and backs up the current slot first). Testers then carry saves across builds and machines, and can attach one to a bug report.
7. **Fixtures pin the formats.** tests/fixtures/saves/ holds real saves as JSON:
   - classic v3, v4 and v5;
   - a golf v5 from before T027 (no height or progress);
   - a golf v5 from today's main, with height chunks, progress, structures, parcels and cards.
   A golden test loads each through `upgradeSave` and the golf normalizers and checks key facts (segment count, golf tier, height chunk count, progress).
   **Rule:** any PR that changes the save shape adds a fixture written by the build before it.
8. **Size.** The course height worst case is every 16×16 block non-zero: 4,096 chunks × 258 numbers ≈ 1.06 M numbers, about 3–4 MB of JSON before gzip. A test pins it: the gzip size of a fully edited field must stay under 2 MB. No new encoding unless the test fails. IndexedDB holds it easily; the cost is save time, and the autosave is already debounced.

## Not in Alpha
- More than one save slot, cloud saves, and save thumbnails (Beta P14 settings, if wanted).
- Reading saves from a *newer* build in an older one. It's refused safely (decision 3), never guessed.
