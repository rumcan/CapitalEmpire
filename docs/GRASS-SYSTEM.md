# The grass and ground: what exists today (for the agent building grass management)

The owner asked another agent to build a grass management system (wear and tear, new textures and more). This page says what is
already in the game, where it lives, who owns which file, and how to test it, so that agent can build on it rather than next to it.
Written by the art chat on 2026-10-22 (main after "Map decals"). Read `CLAUDE.md` and `docs/SECOND-AGENT.md` (who owns what) too.

## 2. Golf grass that already has state

- **Seed or sod, and grow-in** (the coder, G-series): a golf area painted in golf mode carries `plantKind` (`'seed' | 'sod'`) and
  `plantedMonth` (absolute month index) on `PaintArea` (save tuple elements 12 and 13). Until grown it shows the **New sod** texture
  (`golfSod`); `golf/costs.ts` `SURFACE_COST` has per surface `seed`, `sod`, `growIn` (months) and `upkeepYear`. Course quality counts
  unfinished areas (`golf/coursestats.ts`). Engine side: `engine.ts` (golfMonthIndex and the monthly re-send of growing areas only).
- **Hole tags**: paint areas carry optional `hole` (1–18) and `kind` (fairway, green, tee, rough, bunker, water, cart path; tuple 10, 11);
  `golf/holeview.ts` reads them for par, lengths, pins and tee markers.
- The **photo textures** for golf: `golfGreen`, `golfFairway`, `golfSod`, `golfRough`, `golfFringe`, `golfTee`, `golfFirstCut`,
  `golfFescue` and others (`grass-art.ts` `GrassTex`). `EAGER_PHOTO` are loaded at start; the rest load when first used.

Wear and tear does **not** exist yet for grass: nothing tracks foot traffic, carts or events on grass, and nothing changes a painted
area's look over time except grow-in.

## 3. Where a wear system could hook in (suggestions, not decisions)

- **Per-area state** fits on `PaintArea` like `plantKind` / `plantedMonth`: new optional trailing tuple elements (after 18) keep old saves
  loading. Bump nothing in the existing slots (`paint.ts` comment above the tuple says what each slot is).
- **Look**: a worn state can swap the texture (as grow-in swaps to `golfSod`), or blend a worn picture over it. The border band already
  has its own texture and style, which suits worn edges.
- **Map-wide grass** (not painted areas): the base grass is one tiled texture, so per-place wear there needs a new layer (a mask
  painted into the chunk, like the wheel wear by roads) or decals placed from game state (see `map-decals.ts`: placement is a pure
  function of a box and settings; a state-driven layer can follow the same shape).
- **Re-baking**: after a change, mark the chunks stale through the ground cache (look at how a paint edit does it in `engine.ts`); do
  not re-bake the whole map.
- **Settings the owner tunes** belong in the studio (the owner's rule: give every option and the controls to tweak it, never pre-pick).
  The Ground tab (`scripts/assets/review/ground.js`, server routes in `server.mjs`, shared code bundled through
  `scripts/assets/review/ground-lib.ts`) is the pattern: the game module exports pure functions + a `clamp…` for its json, the studio
  imports the same module for its preview, Save writes the json, Rebuild game sprites builds the game.

## 4. Who owns what (from SECOND-AGENT.md)

- **The coder**: `src/App.tsx`, `engine.ts`, `paint*.ts`, `golf/**`, `renderer.ts` (except the `GROUND_PHOTO` / `GROUND_SCALE` maps at
  its top), `textures.ts` (except its photo parts), every other `src/game/*.ts`, `tests/**` for those.
- **The art chat**: `art/**`, `scripts/assets/**` (the studio), `src/assets/**`, `grass-art.ts`, `lot-decals.ts`, `base-grass*.ts`,
  `map-decals.ts`, the generated libraries.
- Working in another agent's file is fine when needed: keep the change small and write a line in that agent's log in SECOND-AGENT.md.

- The copied repos belong to the old PC's Windows user: git needs `safe.directory` (per command:

- Game: `npm run build`, then `npx vite preview --host 127.0.0.1 --port 5174 --strictPort` (the owner tests on 5174; rebuild after
  every landing). Studio: `node scripts/assets/review/server.mjs --port 5179` (the game shows a **Studio** link on localhost).

  origin/main, push.
