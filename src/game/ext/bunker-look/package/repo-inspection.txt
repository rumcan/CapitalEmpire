FAST RUNTIME HANDOFF

1. On course design/style/height edit, update only the affected bunker/corner region and its complete old/new dirty reach.
2. Prepare material images once per worker (or share cloned ImageBitmap snapshots, as the existing texture pack does).
3. Bake the selected depth/profile once, outside the animation frame. If the profile changes during that bake, replace/discard by revision.
4. Keep one projected raster at a sufficient top resolution; lazily cache lower raster levels or derive their mip images. Do not keep all four exported height alternatives decoded by default unless they are actually in use.
5. Composite that raster into the existing worker ground chunk at the correct draw-order stage, then let the normal bitmap-transfer/upload/cache path handle frames.
6. The per-frame path stays cached 2D GL chunk draws. Do not run SDF generation, triangle mesh building, shader compilation, grass blade expansion or image readback per frame.
7. Planner/distant views should reuse the game's simplified course fill and existing LOD policy. Fine roots and sand rake detail need not be redrawn at far zoom.
8. Match premultiplied-alpha conventions at bitmap creation/upload. Keep a conservative transparent gutter for bilinear filtering and wall/shadow reach. Document whether colour/shading is already baked so the newer shade-mask pipeline does not apply it twice.
9. Preserve deterministic global material coordinates across chunk boundaries. The four PNG sections of one edited outline are an export layout, not interchangeable universal corner tiles.

The newer cached origin/main already follows the broad bake-on-edit architecture; exploit that rather than introducing a second runtime WebGL scene or modifying the game's texture-array sprite atlas for a ground-only asset.

GEOMETRY AUTHORING AND THE PACKAGED CONVERSION

CourseLayer.fill rings are closed but clipped to the chunk box with a 0.1-tile overlap. They are not complete feature outlines. Rendering every clipped ring independently creates walls across chunk seams. Combining overlapping chunk fills into one global even-odd path can also cancel overlap strips into holes.

CourseLayer.edges contains only true physical boundaries. Its polylines are open where cut at a chunk boundary, and a whole enclosed ring repeats its first point. Assemble neighbouring true runs globally until every boundary node has degree two, then create complete rings; preserve components and holes. An incomplete neighbourhood must fail explicitly or wait for more neighbours. It must never close an open run with an invented segment. Alternatively pass whole feature rings from the authoritative existing bunker geometry.

CourseWall.p is x,y,drop triples: x/y tiles, drop metres. CourseRim.p is x/y pairs. The higher side is on the left. The packaged conversion preserves these as read-only appearance-source data; it does not rewrite the game grid. Rim candidates include their original source patch because hi alone cannot establish bunker ownership.

    drawBunkerIntoChunk(ctx, completed, {
      worldX0: X0, worldY0: Y0, rasterScale: L
    });
  }

These helpers intentionally do not monkey-patch private methods, replace a game's whole CoursePatch, create workers in the game, or register assets by themselves. Binding this package into the current private drawCourses pipeline still requires a deliberate future game code change. The present task packages the replacement adapter and its contract without installing or modifying the game.

COMPONENT BAKES, AUTHORITATIVE RINGS AND CHUNK DRAW CULLING

The canonical runtime is bunker-border-kit/integration/runtime (not an earlier edge-matched sibling).

splitBunkerComponents(ringsTiles) returns:
  Array<{ringsTiles:Float64Array[],componentKey:string,boundsTiles:[x0,y0,x1,y1]}>

Complete, nonintersecting rings use even-odd containment. Each outer ring keeps its immediate holes; a sand island nested inside a hole becomes its own component, with its own holes. Disconnected bunkers therefore get separate bounded images instead of sharing a downsampled 64-tile course bitmap. Input ring order, winding and start vertex do not change componentKey. Identical ring pairs cancel under even-odd fill.

componentKey is a geometry/cache identity, NOT a stable course entity ID. Geometry edits can change it. The caller must keep a component registry tied to the existing bunker/owner identifiers, preserve those identifiers across edits, and retain the previous dirty bounds for replacement/removal. If the game's grid has no separate bunker entity, this registry remains render-only; do not create a new physics/navigation/save entity just to hold a component image. Source CoursePatch/grid/ball/collision/navigation data stays unchanged.

Typical binding sequence:
  geometry = extractBunkerGeometry(allRequiredNeighbourPatches);
  components = splitBunkerComponents(geometry.ringsTiles);
  for each component:
    existingId = callerOwnedComponentRegistry.resolveExistingOwner(component);
    request = buildBakeRequest({
      id: existingId, revision: existingEditRevision,
      ringsTiles: component.ringsTiles,
      appearance: approvedAppearance,
      previousDirtyBounds: registry.previousDirtyBounds(existingId),
      rasterScale: 0.6, maxEdge: 1024
    });

The registry resolver is the game's binding responsibility, not a new entity generator in this helper. Never use the changing componentKey as the persisted gameplay ID. Retire stale image/cache records when a component is removed or replaced, while invalidating the union of its old and new reachable bounds.

buildBakeRequest now carries ringsTiles as independent Float64Array copies of the exact input coordinates. Game Float32 coordinates remain exactly representable; higher-precision caller coordinates are not quantized down. Its deterministic key includes these exact rings. A sub-tile edit therefore changes the bake key even if the coarse vertex guide is byte-for-byte unchanged.

Exact game rings are the production boundary authority. The production baker must construct its vector-ring SDF from request.ringsTiles and bypass authoring-guide re-rounding/contouring when they are present. The one-tile/2m guide remains useful for bounds and standalone authoring fallback. Appearance.roundness affects guide-authored shapes only; it must not reshape a game's already-authored outline. The helper does not mutate the original rings or game CoursePatch data.

drawBunkerIntoChunk now checks the projected destination rectangle against ctx.canvas.width/height when available and returns false before any save/draw if wholly outside. Partial overlaps still draw through the caller's existing clip. Context state is restored on success and on drawImage failure; fake/non-canvas contexts retain the previous drawing behavior.

Native pass ownership remains conditional: only a valid bake whose key matches the current request activates replacement. While pending, missing or stale, native sand/lip/wall/rim/floor-light passes stay active. Once ready, replace only this existing bunker's owned floor/wall/lip spans at their native stages; never suppress unrelated native materials, shared neighbours or all rims globally.

The canonical test-capital-empire-adapter.mjs verifies component+hole grouping, nested islands, ring-order/winding/start-invariant geometry keys, exact Float64 copying, source immutability, same-guide/different-key sub-tile edits, duplicate even-odd cancellation, outside-canvas culling, partial placement, context restoration and pending native fallback. It does not claim in-game installation or performance measurements.
